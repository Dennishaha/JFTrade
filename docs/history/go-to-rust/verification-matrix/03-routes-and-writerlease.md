### 2.3 领域 3：278 条路由全景矩阵与 WriterLease 单属主（278-Route Matrix & WriterLease Ownership）

#### 2.3.1 Go 基线路径、符号、关键行号与历史行为

- **历史行为**:
  Go 基线维护了一套 OpenAPI 规范路由，总数为 278 条。Go 架构中各个模块直接通过内存共享或独立的 SQLite 连接池访问数据库，没有统一的进程级或文件级排他租约机制，无法有效防止多进程同时挂载同一个 SQLite 文件导致的数据库锁争用或元数据损坏。

#### 2.3.2 Rust 当前实现路径、符号、关键行号与架构机制
- **源码路径**:
  - `crates/jftrade-engine/src/product_production_route_manifest.json` (SHA-256: `afa112435ed280dd24d43bb4acaa0f7ca2ab45c01e4e5701efc5ce149e5b85b2`)
  - `crates/jftrade-api/src/envelope.rs:35-90`
  - `crates/jftrade-owner-lock/src/lib.rs:73-128`
  - `crates/jftrade-engine/src/product_production_database_leases.rs:10-215`
  - `crates/jftrade-engine/src/product_production_dispatch.rs:225-240`
- **关键机制**:
  1. **路由完全等价性**: Rust 生产路由清单与 Go 基线 100% 吻合，精确覆盖 **278 条规范路由**。
  2. **ApiFailure 统一响应规范**: 统一使用结构体 `ApiFailure { status, code, message, retry_after_seconds }`，返回 JSON 格式为 `{ "ok": false, "error": { "code": "...", "message": "..." }, "timestamp": "..." }`，当包含 `retry_after_seconds` 时自动下发 `Retry-After` HTTP 响应头。
  3. **只读路由绝对隔离**: 149 条 GET 路由通过不可变引用 `&self` 调用，禁止任何 `BEGIN IMMEDIATE` 写事务，K 线与快照查询严格从内存或网关只读获取，绝对不向 SQLite 回写缓存。
  4. **9 SQLite 单写入属主 (WriterLease)**: 纳管的 9 个 SQLite 数据库在启动时通过 POSIX `fcntl` / Windows `LockFileEx` 获取排他文件锁（`<dbname>.db.lease`），写入进程 PID 与启动时间。任何其他进程试图并发打开将触发 `WriterLeaseError::Held`，启动流程立即逆序清理并终止，彻底防止多进程双写。

#### 2.3.3 微观差异与破坏性边界失效推演
1. **跨三库无全局 2PC 提交导致的孤儿数据 (Crash Gap)**:
   - **时序推演**: ADK 执行工作流任务，向 `adk.db` 写入任务、`adk-session.db` 写入事件，但在写入 `adk-artifact.db` 之前遭遇断电。
   - **失效后果**: 会话事件中引用了工件 ID，但工件库中无对应内容。
   - **防御机制**: 读取端 `get_artifact` 显式进行 `Option` 判空，缺失时映射为 `NOT_FOUND`，避免界面抛出未捕获异常。
2. **单进程多线程文件锁误判 (Process-level Locks)**:
   - **防御机制**: Rust 架构中所有数据库的 Store 实例均由 `open_production_stores` 在单线程启动阶段统一创建，并封装为唯一的 `Arc<T>` 跨线程共享，从类型系统层面彻底根除了同一进程内重复申请写锁的隐患。
